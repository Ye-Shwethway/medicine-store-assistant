# Password Recovery Delivery Channels

Status: **planned; delivery automation not yet implemented**

F7.2C already owns reset-token security: enumeration-safe request, short-lived single-use reset token, digest-only verifier storage, credential-version/session invalidation, and account-security events.

This document defines the future delivery layer around that verified lifecycle.

## Normal target workflow

Routine forgotten-password recovery should not require the Owner to manually copy every reset link.

Preferred channels:

- verified recovery email;
- securely linked Telegram account;
- Owner-assisted issuance as fallback only.

The MSA backend remains the authority that creates and validates reset tokens. Email and Telegram are transport adapters only.

## Verified email

A recovery email address must be verified before it can receive password-reset links. Verification state belongs to the canonical user account. Provider-specific delivery credentials remain runtime secrets.

Do not hard-code a vendor into the architecture. Select a transactional-email provider at implementation time based on current cost, deliverability, domain-verification support, API/SMTP reliability, and data-handling requirements.

## Telegram

A Telegram identity must be linked to the canonical `user_id` through an authenticated pairing/challenge flow. Entering an arbitrary Telegram ID is not sufficient to establish recovery authority.

Once linked, the MSA Telegram bot may deliver reset links or equivalent one-time recovery actions generated by the backend.

## Security invariants

- public reset-request responses remain enumeration-safe;
- reset tokens remain short-lived, single-use, cryptographically random, and digest-only at rest;
- delivery providers never receive password hashes, database credentials, roles, or inventory authority;
- retries/rate limiting/abuse controls/delivery state are deterministic backend behavior;
- delivery failure does not weaken token policy or disclose account existence;
- provider secrets never enter Git or browser storage;
- Owner-assisted reset remains available for users without a verified recovery channel or when delivery fails.

## Implementation placement

Implement delivery adapters with F7.8 Alerts & Notifications, or as a narrow prerequisite during Telegram account-linking work. Until then, the deployed Owner-assisted F7.2C reset remains the operational fallback.
